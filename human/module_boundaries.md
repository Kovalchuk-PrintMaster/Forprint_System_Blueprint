# Module Boundaries

Цей документ фіксує межі відповідальності модулів. Якщо модуль починає робити чужу роботу, це потенційний architecture drift.

## CRM

`forprint_crm` — це не фізичне сховище всіх бізнес-даних. Це бізнес-диригент, інтерфейс для людей, центр узгодження процесів, аналітики і статусів.

CRM може показувати клієнтів і замовлення, але канонічні записи мають належати відповідним реєстрам.

## Telegram Bot

`telegram_bot` — це операційний інтерфейс і виконавець сценаріїв. Він не є джерелом правди для цін, клієнтів, бухгалтерії або довідників.

## Library

`forprint_library` — джерело правди для довідників, матеріалів, техкарт, шаблонів, режимів друку, номенклатури.

## Calculator

`calculator_engine` — джерело правди для розрахункової логіки, калькуляцій, кошторисів і оцінок витрат матеріалів.

## Operational Registry

`forprint_operational_registry` — майбутній / плановий реєстр операційних бізнес-записів: клієнти, замовлення, взаємодії, робочі статуси.

## Accounting Registry

`accounting_registry_service` — бухгалтерський і 1С-сумісний контур: рахунки, оплати, акти, бухгалтерські документи, експорт / синхронізація з 1С.
