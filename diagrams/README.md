# Blueprint Diagrams

This directory contains Mermaid architecture diagrams for the ForPrint System Blueprint.

The diagrams are human-readable architecture artifacts. They help the operator, module assistants and future inspection tools understand the current ForPrint ecosystem structure, data flows and ownership boundaries.

## Purpose

Diagrams are used to make Blueprint architecture visible.

They should help answer:

```text
which modules exist;
how modules are connected;
which module owns which data objects;
where customer channels enter the system;
where Gateway, CRM, Operational Registry, Library, Calculator and Accounting fit;
which parts of the system are planned, active or external.
Diagram files
module_graph.mmd

Generated module relationship graph.

Generated by:

make diagrams

Current generator:

scripts/generate_mermaid.py

Primary source:

machine/data_flows.yaml
ownership_map.mmd

Generated ownership map showing which module owns which data object.

Generated by:

make diagrams

Current generator:

scripts/generate_mermaid.py

Primary source:

machine/ownership.yaml
data_flow.mmd

Tracked high-level data flow diagram.

This is a compact human-readable overview of the main ForPrint data movement.

project_landscape.mmd

Tracked project landscape diagram.

This shows the main local project directories and important external/support modules.

system_detail_map.mmd

Tracked detailed system map.

This is a more explanatory architecture diagram for human review.

Generated versus manual diagrams

Some diagrams are generated from machine-readable Blueprint files.

Some diagrams are manually maintained human-readable architecture views.

Generated diagrams should be refreshed with:

make diagrams

Manual diagrams should be edited deliberately and reviewed as architecture documentation.

Update policy

When machine sources change, run:

make diagrams

When diagram documentation or index changes, run:

make diagrams-check

Before committing diagram-related changes, run:

make lint
make test
make check-report
Future direction

ForPrint Project Inspector may later verify that:

diagram files exist;
generated diagrams are up to date;
diagram index entries are valid;
human-facing architecture views are present;
diagram sources are documented.
Boundary

Diagrams are documentation and architecture visibility artifacts.

They do not define business truth by themselves.

Machine-readable Blueprint files remain the canonical architecture source.
