# Integration Audit Checklist for Tomorrow

Before changing roadmaps, inspect what already exists.

## Telegram Bot
- Current declared mission.
- Existing intent/style/sentiment model.
- Existing Mistral fallback.
- Existing customer context/profile concepts.
- Existing communication templates.
- Existing order/clarification flow.
- Existing conversation-state ownership.
- Existing dependencies on Calculator/CRM/Registry/Prepress/Logistics.

## CRM / Account Manager
- Customer profile ownership.
- Customer history.
- Customer commercial state.
- Manager-assigned policies.
- Customer segmentation.
- Analytics/attention surfaces.

## Operational Registry
- Operational truth boundary.
- Order state.
- Process/work state.
- Existing timers/deadlines/escalations.
- Existing event model.
- Suitability as temporary Process Manager host.

## Accounting Registry Service
- Payment status.
- Credit/debt concepts.
- Invoice/payment history.
- Source of finance-related customer evidence.

## Logistics
- Shipment state.
- Carrier/provider state.
- Reminders/tracking.
- Long-running delivery processes.
- Whether current workflow concepts already exist.

## Prepress Hub
- Asset analysis.
- File fingerprints.
- Historical asset indexing.
- Page/document inspection.
- Candidate comparison.
- Archive access boundaries.

## Calculator Engine / Library
- Canonical product/material/format constraints.
- Pricing truth.
- Order configuration.
- Whether confirmation UI can consume their contracts.

## Blueprint / Control Plane
- Dispatcher semantics.
- Q1–Q8 clarification/escalation.
- Operation tunnels.
- Roadmap package.
- Capability graphs.
- Worker/process terminology collision risks.

## Cross-cutting
- What is canonical?
- What is derived?
- What is generated?
- What is a communication surface?
- What is business truth?
- What is customer descriptive evidence?
- What is policy/authority?
- What should be event-driven?
- What should be periodically reconciled?
