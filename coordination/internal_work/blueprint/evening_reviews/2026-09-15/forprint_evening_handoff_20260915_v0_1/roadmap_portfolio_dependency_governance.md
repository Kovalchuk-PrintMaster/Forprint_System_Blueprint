# Roadmap / Portfolio / Dependency Governance

## Operator-facing roadmap
Use human-readable descriptions first: finished, current, why it matters, next 3-5 meaningful steps, and important subwork. Machine IDs are secondary.

## Human provenance
Human-confirmed roadmap intentions retain concise rationale extracted from live discussions.

## Synthetic/provisional future
Known future work must not disappear because details are incomplete. Use explicit provisional markers and a refine-before-execution gate.

## Dynamic roadmap mutation
Meaningful insertion/reordering requires:
- dependency graph/matrix recompute;
- cross-module impact validation;
- readiness/order recompute;
- dispatcher queue/prompt consequences;
- portfolio/projection refresh;
- consistency validation.

## Minor vs major
Minor bounded local changes may ride current flow.
New functionality, substantial integration work or dependency changes belong in roadmap.

## Waves
After module deep audits, build global dependency matrix and development waves to final targets.

Operator-stated current high-priority group: Logistics, Telegram, Calculator. Reconcile with canonical priorities before making authoritative.
