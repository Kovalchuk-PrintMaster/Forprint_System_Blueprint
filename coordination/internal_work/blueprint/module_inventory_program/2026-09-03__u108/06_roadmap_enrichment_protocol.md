# Roadmap Enrichment Protocol

Reconciliation classes:
VERIFIED_IMPLEMENTED / PARTIALLY_IMPLEMENTED / NOT_STARTED / BLOCKED /
SUPERSEDED / PROPOSED_NEW / NEEDS_REWRITE

Rules:
1. Code existence alone does not prove completion.
2. Completion must match intended current semantics.
3. Historical code may satisfy only part of a future step.
4. Useful discovered behavior may become PROPOSED.
5. Wrong-module functionality becomes ownership/migration work, not mandate expansion.
6. Cleanup, deprecation, contracts, tests, observability and migration are valid roadmap work.
7. Keep approximately ten meaningful forward steps.
8. Keep dependency gates explicit.

Every module ends with a mature-state sentence.
