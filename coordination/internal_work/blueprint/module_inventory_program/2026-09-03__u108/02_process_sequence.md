# Canonical Next-Phase Process Sequence

## P0 — Blueprint continuity
Validate Blueprint state, current release, identity registry, indexes, roadmaps, Human Intent, and hard gates. Integrate this inventory program and ensure fresh-context continuity.

## P1 — Portfolio triage
For all canonical modules record repository location, size, age/history risk, current-state evidence, roadmap maturity, ownership concerns, legacy risk, documentation-conflict risk, and inventory priority.

## P2 — Repository partition
Split each repository into logical archive batches: root/docs/config, core source, interfaces/contracts, persistence, integrations, tests, tools, historical/legacy, generated/reports, runtime/deployment. Merge or split based on size.

## P3 — Batch analysis
Human uploads one archive. Assistant returns one durable report. Reports are stored in the module inventory working directory.

## P4 — Module consolidation
Combine reports into one evidence baseline: capability map, active/historical lineage, documentation authority, ownership conflicts, tests/evidence, blockers, dependencies.

## P5 — Blueprint enrichment
Update portfolio knowledge from evidence. Do not distribute work.

## P6 — Roadmap enrichment
Reconcile current roadmap against evidence and discovered useful functionality.

## P7 — Module bootstrap substrate
Prepare module inventory/index, AGENTS.md, coordination/reporting v0.4.1 integration, and local inventory/index maintenance design.

## P8 — Cleanup plan
Resolve contradictory active instructions, isolate/deprecate historical code/docs, define canonical read order, prepare migrations for functionality owned elsewhere.

## P9 — Readiness verification
Check repository understanding, documentation clarity, coordination compatibility, tooling, safety, and portfolio dependencies.

## P10 — First bounded implementation wave
Only after explicit human approval. Do not release all modules at once; use dependency-balanced waves.
