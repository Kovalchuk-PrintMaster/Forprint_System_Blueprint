# Telegram Bot — Conversational Operating Interface Target State v0.1

Status: PROVISIONAL / SYNTHETIC / STRATEGIC CORE / FREQUENT REFINEMENT EXPECTED

Telegram is not a menu bot. Target state is a conversational operating interface that understands
natural communication, maintains relationship context, translates intent into structured
operations, invokes canonical internal modules and returns accurate facts in friendly language.

**Telegram orchestrates; it does not own canonical pricing, product/material, accounting,
logistics or production truth.**

## Identity and memory

Use stable internal customer/contact identity. Telegram id, phone, email and other channels map to
that identity.

Retain conversation history under future retention/privacy policy and maintain structured memory
such as active requests, preferences, order refs, unresolved questions and summaries.

## Repeat-order reconstruction

Preferred evidence order:

`structured order history -> canonical job specification -> production file refs -> relevant conversation -> semantic retrieval if needed`

Current price is recalculated by Calculator.

## Intent, clarification and orchestration

Convert natural language into typed intents/parameters. Ask the minimum useful clarification.
Resolve canonical product defaults through Library/Calculator/other owners.

Likely integrations include Calculator, Library, registries, Logistics, Accounting, Warehouse,
Prepress and future production/equipment-load planning.

## Employee/admin command plane

Authorized internal users may initiate text/voice operations. Authorization uses internal
identity/roles/capabilities, not username text alone. High-impact/money-spending actions use governed
confirmation.

## Voice and multimodal

Speech-to-text feeds the same intent pipeline. Images/previews may be analyzed to find candidates.
Vision is not production truth. Heavy production assets may get lightweight previews without
changing masters.

## Escalation

1. deterministic/structured workflow;
2. AI reasoning assistant;
3. human exception handling.

Before escalation build a focused Context Packet with customer id, intent candidate, relevant
conversation, related orders, file previews, attempts already made, exact unresolved fact,
confidence and safe interpretations.

## Presentation and learning

Use natural friendly language. Critical facts come from structured canonical data.

Prefer explicit/configurable addressing preference rather than storing inferred gender as business
truth.

Support proactive readiness/delay/courier/clarification notifications and track unresolved intents,
clarification loops, escalations, corrections and model/provider performance.

## AI architecture

Do not bind permanently to DeBERTa, Mistral or one provider. Route intent classification, entity
extraction, reasoning, retrieval, vision, speech and response generation through replaceable
model/provider slots.

Existing integrations must be inventoried before reuse/retirement decisions.

## ETA

Future production/equipment-load planning should provide reliable ETA. Until then use governed
fallback lead-time rules; missing dynamic ETA does not block basic Telegram/Calculator launch.
