# Assistant Operating Contract — Module Knowledge Stabilization v0.1

## Mandatory sequence

`preflight → workspace → segmentation → block analysis → synthesis → document reconciliation → capability reconciliation → roadmap linkage → knowledge surfaces → cleanup work package → maintenance automation`

Do not skip from repository scan directly to cleanup or implementation.

## Rules

1. Start from canonical program files, not arbitrary repository documents.
2. Work in bounded functional blocks and produce one report per block.
3. Do not confuse historical provenance with current authority.
4. Before proposing new code, check current/partial/duplicate/legacy/reuse/migration candidates.
5. Do not delete during discovery.
6. Preserve uncertainty explicitly.
7. Keep roadmap state separate from implementation state.
8. Treat wrong-module functionality as a cross-module portfolio candidate, not disposable legacy.
9. Do not build final maintenance automation before the Library pilot proves the model.
10. Assistant Context Pack / Assistant Spark are projections, not authority.
11. End every work session with module, phase completed, blocks completed, outputs, unresolved questions and exact next step.

## Continuity requirement

A replacement assistant must be able to continue from canonical files without reconstructing the entire previous conversation.
