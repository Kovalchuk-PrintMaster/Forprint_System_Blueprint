# CF-10: канонічна межа операторських облікових записів

Статус: **затверджена власником вимога, 2026-11-03**.

- `s01` — ім'я хоста та історичний обліковий запис доступу; **заборонено** використовувати його для ForPrint PAM, `sudoers` та Worker ownership. Заборонено розширювати його привілеї.
- `forprint-operator` — єдиний спеціальний обліковий запис для operator/owner PAM. Пароль вводиться у терміналі; не зберігається та не передається у повідомленнях.
- `forprint-runner` — окремий мінімально привілейований systemd Worker account. Не використовується для PAM, не має sudo та інтерактивного входу.
- Єдине канонічне джерело імен — `coordination/continuity/cf10_operator_identity_policy_v0_1.yaml`; стару PAM-політику необхідно узгоджувати з ним.
- Не створювати жодних `sudoers`-прав для `s01`. Для `forprint-operator` потрібна окрема перевірена host policy з обов'язковим паролем і лише мінімальною командою `/usr/bin/true`, якщо `sudo -v` використовується як PAM verification. Заборонено `NOPASSWD`, надання широких sudo-прав і автоматичну зміну паролів.
- Source-controlled PAM console, policy та тести мають бути published у тому самому Git HEAD. Після source commit **не запускати заморожений `cf10-u180j-a050`**, підготовлений на старому HEAD. Створити новий attempt через канонічні Make/CLI; не переписувати frozen manifests чи root PRECLAIM вручну.
- Існуючі r059–r063 лабораторні докази лишаються історичними доказами тестів. Будь-який новий release кандидат повинен мати новий exact HEAD/attempt binding та незалежний operator review.
